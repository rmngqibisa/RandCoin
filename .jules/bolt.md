## 2024-12-02 - Block Mining Inner Loop Optimization
**Learning:** String concatenation and `.encode()` inside a tight CPU loop like Proof-of-Work adds measurable overhead due to repeated object allocations. By moving to byte string formatting (`%d`) and replacing string operations with bytes outside the loop, overhead is minimized. Localizing attribute lookups (`self.nonce` -> `nonce`) and standard library functions (`hashlib.sha256`) further reduces function call overhead.
**Action:** When optimizing tight computational loops (like PoW mining), minimize attribute lookups, avoid repeated string-to-byte encodings, use format strings in byte mode, and ensure any string formatting handles payloads safely (e.g. escaping `%`). Also ensure that dictionary initialization respects key ordering when relying on dictionary hashing to avoid mismatches.
