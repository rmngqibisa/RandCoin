## 2024-05-24 - Python Loop Overhead in Blockchain Mining
**Learning:** String concatenation (`str + str + str`) and `.encode()` method calls inside a tight `while` loop (like Proof of Work mining) incur significant Python interpreter overhead and object allocation costs. Additionally, calling `json.dumps` recursively inside an integrity check hash calculation can be extremely expensive, hence why pre-sorted dictionary schemas are critical for deterministic performance in this codebase.
**Action:** When optimizing tight CPU-bound loops in Python (like hashing), hoist method lookups (e.g., `sha256 = hashlib.sha256`) out of the loop and utilize byte-string formatting (e.g., `b'{"nonce": %d...}' % nonce`) instead of building and encoding unicode strings per iteration. Always escape `%` characters when doing byte formatting on arbitrary string content like JSON!
